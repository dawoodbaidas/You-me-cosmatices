# تشغيل إدارة YOU & ME

## تطبيق قاعدة البيانات

الترحيل الجديد: `supabase/migrations/004_admin_merchandising.sql`، بعد `001` و`002` و`003`. لم يُطبّق على Supabase المتصل أو الإنتاج.

1. خذ نسخة احتياطية، وجرّب الترحيل على مشروع Supabase تجريبي أولاً.
2. افتح SQL Editor للمشروع الصحيح، ثم نفّذ **محتوى ملف 004 كاملاً مرة واحدة**. الملف داخل `BEGIN / COMMIT`؛ أي خطأ يلغي العملية كلها. لا تعِد تشغيل `seed.sql` أو migrations القديمة.
3. حدّث أنواع PostgREST بإرسال `NOTIFY pgrst, 'reload schema';` إذا لم تظهر العلاقات الجديدة فوراً.
4. شغّل نسخة التطبيق الجديدة بعد نجاح الترحيل. حدّث جلسات الأدمن القديمة قبل تعديل أسعار الأنواع؛ أصبحت أسعار الأنواع أسعاراً أصلية وتُطبّق عليها نسبة خصم المنتج.

يضيف الترحيل:

- `products.original_price`, `discount_enabled`, `is_new` مع قيود تحقق. يبقى `price` السعر الفعلي و`old_price` السعر الأصلي عند الخصم، وتُستعاد الأسعار الأصلية عند تعطيله.
- `home_sections` و`home_section_products` للقائمتين المرتبتين، مع منع التكرار وحفظ الإصدار لمنع الكتابة فوق تعديلات جلسة أخرى. الهيرو حتى خمسة منتجات بما يلائم تصميمه الحالي؛ الأكثر طلباً حتى 100. يمكن للمنتج الظهور في القائمتين.
- `store_orders` و`store_order_items` لتثبيت الأسعار والأسماء والعملة ورسوم التوصيل عند اعتماد الطلب. هذه طلبات إحالة إلى واتساب، وليست دليلاً على دفع مبلغ أو استلام الطلب، ولا تحجز المخزون.
- دوال أدمن للترتيب، والنقل الجماعي، وحذف القسم وإعادة التصنيف في معاملة واحدة. حذف قسم يعالج المنتجات المرتبطة به مباشرةً، ويُبقي أقسامه الفرعية وينقلها للمستوى الأعلى. يُستبدل تصنيف المنتجات المتأثرة بالقسم الهدف أو يصبح فارغاً وفق الاختيار، ولا تُحذف المنتجات.

المنتجات القديمة تبقى بأسعارها الحالية. تُنقل الخصومات ذات `old_price > price` وشارة `new/جديد` الموجودة مسبقاً. أسعار الأنواع القديمة المخفّضة تُحوّل إلى أسعار أصلية مع الحفاظ على السعر الفعلي بدقة العملة (0.001). الاختيارات الثابتة السابقة في `scene-products.ts` تُنقل مرة واحدة. القائمة الفارغة المحفوظة لا تُملأ تلقائياً. قبل تطبيق 004، غياب القوائم الجديدة يسمح بالاختيارات السابقة للتوافق فقط.

للرجوع عن نسخة التطبيق، أبقِ الجداول والطلبات الجديدة والنسخة الاحتياطية؛ لا تحذف بيانات الطلبات ولا تعكس تحويل أسعار الأنواع بعد بدء استقبال طلبات. الرجوع لنسخة قديمة يحتاج إعادة مواءمة أسعار الأنواع من النسخة الاحتياطية قبل إتاحة التحرير، أو إصلاحاً أمامياً. لا يوجد down migration يحذف البيانات.

## الصور وStorage

يستمر استخدام المخزن العام `product-images` ومسارات `products/<product-uuid>/<file-uuid>.<extension>`. يحدّث 004 أنواع MIME وسياسات الإدخال والتعديل لدعم PNG وJPEG وWebP وGIF وAVIF وTIFF، بحد 4 MB. لا حاجة إلى مخزن جديد أو مفتاح service_role.

عند تعطيل «إزالة الخلفية»، تُرفع بايتات الصورة الأصلية دون تحويل. عند تفعيله، تذهب الصورة إلى معالج الخادم، ويظهر WebP شفاف في المعاينة على خلفية مربعات. لا يُرفع الملف إلى Storage حتى حفظ المنتج. تبقى الصورة الحالية مرتبطة بالمنتج حتى نجاح الرفع والمعاملة؛ فشل المعاملة المؤكد ينظف الملف الجديد غير المرجوع إليه. عند نتيجة اتصال غير محسومة نحتفظ بالملف بدلاً من المخاطرة بحذف صورة ربما حُفظ ربطها؛ راجع الملفات اليتيمة بعد التحقق من مراجع `products.image_url`.

أضف إلى **بيئة الخادم فقط**:

```dotenv
REMOVE_BG_API_KEY=your_private_api_key
```

لا تضف بادئة `NEXT_PUBLIC_`. تبقى متغيرات Supabase الحالية كما هي. يحتاج الخادم Node.js وSharp (مثبت بالفعل)، واتصال HTTPS إلى `api.remove.bg`، ومهلة تشغيل لا تقل عن 60 ثانية لمسار المعالجة. الخدمة قد تستهلك رصيداً؛ إعادة المحاولة تعيد طلب المعالجة. لا يُستدعى المعالج مجدداً عند الحفظ، بل تُرفع نتيجة المعاينة نفسها.

المعالجة تستعمل [remove.bg API](https://www.remove.bg/api) لإزالة حقيقية للخلفية؛ يتحقق الخادم من وجود بكسلات ألفا شفافة ومحتوى مرئي قبل قبول النتيجة. أظهرت وثائق الخدمة وقت الفحص إشعار انتقال إلى Leonardo.Ai اعتباراً من 1 ديسمبر 2026؛ تحقّق من صلاحية حسابك ومفتاحك وتفاصيل الانتقال قبل التشغيل بعد ذلك التاريخ. لم يُختبر الاتصال بالخدمة المدفوعة أو جودة فصل صور الكتالوج الحقيقية لعدم توفر مفتاح اختبار.

## التسعير والطلبات

قاعدة العرض في `src/lib/pricing.ts`؛ نسبة خصم المنتج تُطبّق على السعر الأصلي للنوع المختار، ويُقرّب السعر إلى 0.001 بحساب صحيح يطابق PostgreSQL. `price` للمنتج هو سعره الفعلي، وأسعار `product_variants.price` أسعار أصلية. السعر المشطوب للنوع هو سعره الأصلي. لا تغيّر هذه الدلالة عند استيراد بيانات جديدة.

تحتفظ السلة بالسعر المشاهد وقت الإضافة للمقارنة فقط. المصدر المعتمد دوماً قاعدة البيانات: `prepareCheckout` يقرأ الكتالوج دون كاش، و`create_store_order` يعيد حساب الأسعار والمخزون والإجمالي داخل المعاملة مع قفل الصفوف أثناء تثبيت الطلب. لا تقبل القاعدة سعر المتصفح كمرجع. عند الاختلاف، تعاد تفاصيل السعر والإجمالي لتأكيد الزبون قبل إنشاء سجل. السلال القديمة التي لا تحمل سعراً محفوظاً تستخدم السعر المعروض الحالي للمقارنة. تحتوي رسالة واتساب على رقم الطلب، وتُبنى من نسخة الطلب المحفوظة. جداول الطلبات للقراءة بواسطة الأدمن فقط؛ لا تسمح سياسات RLS بتعديل أسعار الطلبات القديمة من المتصفح.

كل عمليات حفظ المنتجات والأقسام والقوائم تُبطل كاش الكتالوج والصفحات. مشغلات القاعدة تزيد `store_revision` فتصل التحديثات إلى الزوار عبر مسار التحديث الموجود.

## التحقق

```powershell
npm test
npm run typecheck
npm run lint
npm run build
```

`tests/admin-merchandising.test.mjs` يختبر migrations الفعلية على PostgreSQL معزول عبر PGlite، وترتيب القوائم وإفراغها، والحذف والنقل الذريين، ورفض الصلاحيات، ودقة الخصومات، وتثبيت سعر الطلب، وتأكيد السعر المتغير، وبادجات البطاقات في الحالات الأربع، وبايتات الرفع الأصلية وتنظيف الملف عند فشل الربط. اختبار الشفافية يحاكي استجابة المعالج الخارجية ويقرأ قناة ألفا الفعلية في WebP الناتج، ولا يدّعي اختبار نموذج remove.bg نفسه.

أُجري أيضاً `tests/merchandising-browser.mjs` في Chrome على نسخة تطبيق وقاعدة معزولتين، بعرض 390 و1440 بكسل. شمل الحالات الأربع للبادجات، وبقاء بطاقة السعر، وتحديث السلة بعد إلغاء الخصم، وتأكيد السعر وإنشاء طلب محلي، وترتيب الهيرو بعد إعادة تحميل الصفحة، وإخفاء القوائم الفارغة. تنقّل واتساب الخارجي استُبدل بالتقاط الرابط؛ لم تُرسل أي رسالة. لإعادته، شغّل `npm run test:store-browser` ومرّر عنواني التطبيق وقاعدة الاختبار المطبوعين إلى السكربت. هذا لا يحاكي تسجيل دخول الأدمن الحقيقي أو بوابة Storage.

قبل إتاحة الإنتاج، اختبر على Supabase تجريبي متصل: تسجيل الدخول وصلاحيات الأدمن الفعلية، وسياسات Storage ورفع الصور الأصلية والمعالجة بمفتاح الخدمة، وترتيب القائمتين بعد إعادة تحميل المتصفح، وسريان التحديثات لزائر آخر، وتأكيد طلب واتساب بأسعار جديدة. لا تشمل اختبارات PGlite بوابة Supabase Auth/Storage الحقيقية.
